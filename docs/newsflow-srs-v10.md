# 소프트웨어 요구사항 명세서 (SRS)

**시스템명** 뉴스 스크랩 자동화 시스템 (NewsFlow)
**문서 버전** 1.0
**작성 기준** NewsFlow URS v0.2
**표준** IEEE 29148 (SRS) 구조를 따름
**대상 릴리스** 1차 릴리스 (2인 · 7일)
**요구사항 수** 기능 42개 · 비기능 14개

---

## 1. 개요

### 1.1 목적

본 문서는 뉴스 스크랩 자동화 시스템(NewsFlow)이 충족해야 할 소프트웨어 요구사항을 기술한다.
상위 문서인 URS가 사용자 관점의 필요를 기술하는 반면, 본 문서는 시스템이 수행해야 할 동작을 검증 가능한 수준으로 구체화한다.

본 문서는 개발, 검증, 인수의 기준이 된다.

### 1.2 범위

본 시스템은 사용자가 지정한 키워드로 공개 RSS 피드에서 기사를 수집하고, 중복을 제거한 뒤 정해진 시각에 이메일로 전달한다. 수집된 기사는 저장되어 조회할 수 있다.

다음은 본 릴리스의 범위에 포함하지 않는다.

- 워크플로 시각 편집 기능
- 처리 단계의 동적 구성
- 계정 및 권한 관리
- 기사 본문 수집 및 요약 생성
- 이메일 외의 전달 수단

### 1.3 용어 및 약어

| 용어 | 정의 |
|---|---|
| 피드 소스 | 기사를 수집할 대상. 표시명과 주소 템플릿으로 정의된다 |
| 키워드 | 검색어. 주소 템플릿의 치환 위치에 삽입된다 |
| 수집 주소 | 키워드와 주소 템플릿을 결합해 생성된 실제 요청 URL |
| 실행 | 수집부터 전달까지의 처리가 한 번 수행된 단위 |
| 신규 기사 | 저장소에 동일 링크 해시가 존재하지 않는 기사 |
| 링크 해시 | 정규화된 링크의 SHA-256 값. 중복 판단 기준 |
| RSS | Really Simple Syndication. 콘텐츠 배포 형식 |
| SMTP | Simple Mail Transfer Protocol |

### 1.4 참조 문서

| 구분 | 문서 | 비고 |
|---|---|---|
| 상위 문서 | NewsFlow URS v0.2 | 본 문서의 근거 |
| 참고 | n8n 워크플로 「테스트3(수정1)」 | 기존 운영 방식. 검증 기준 |
| 표준 | IEEE 29148 | 요구사항 명세 구조 |
| 표준 | RFC 5322 | 이메일 주소 형식 |
| 표준 | RFC 4287 / RSS 2.0 | 피드 형식 |

### 1.5 요구사항 식별 체계

| 접두어 | 구분 | 예시 |
|---|---|---|
| `SR-F-` | 기능 요구사항 | SR-F-301 |
| `SR-N-` | 비기능 요구사항 | SR-N-101 |
| `SR-D-` | 데이터 요구사항 | SR-D-201 |
| `SR-I-` | 인터페이스 요구사항 | SR-I-101 |

각 요구사항은 상위 URS 요구사항과의 추적 관계를 7절에 명시한다.

## 2. 전체 설명

### 2.1 시스템 구성

| 구성 요소 | 역할 | 비고 |
|---|---|---|
| 웹 클라이언트 | 설정 관리, 기사 조회, 실행 요청 및 상태 확인 | 브라우저에서 동작 |
| API 서버 | 요청 처리, 데이터 관리, 작업 등록 | 동기 응답 |
| 작업 처리기 | 수집·가공·전달 처리 수행 | 비동기 실행 |
| 작업 큐 | 실행 요청의 전달 및 대기 | |
| 스케줄러 | 지정 시각에 실행 요청 생성 | |
| 데이터베이스 | 설정, 피드 소스, 기사, 실행 이력 보관 | |

구성 요소 간 연계는 다음과 같다.

| 출발 | 대상 | 내용 |
|---|---|---|
| 웹 클라이언트 | API 서버 | HTTP 요청 및 JSON 응답 |
| API 서버 | 작업 큐 | 실행 요청 등록 |
| 작업 큐 | 작업 처리기 | 대기 중인 작업 전달 |
| 스케줄러 | 작업 큐 | 지정 시각에 실행 요청 생성 |
| 작업 처리기 | 외부 RSS | HTTP GET 조회 |
| 작업 처리기 | 외부 SMTP | 메일 발송 |
| API 서버 | 데이터베이스 | 설정·기사·이력 조회 및 저장 |
| 작업 처리기 | 데이터베이스 | 기사 저장, 실행 상태 갱신 |

### 2.2 주요 기능

| 기능 | 설명 |
|---|---|
| 설정 관리 | 키워드, 메일 제목, 수신자, 소스당 최대 건수를 등록·변경한다 |
| 피드 소스 관리 | 수집 대상 사이트를 등록·수정·삭제·비활성화한다 |
| 기사 수집 | 키워드와 피드 소스 조합으로 RSS를 조회하고 항목을 추출한다 |
| 중복 제거 | 링크 해시를 기준으로 실행 내부 및 저장소 대비 중복을 제거한다 |
| 결과 전달 | 정렬된 기사 목록을 HTML 메일로 발송한다 |
| 기사 조회 | 저장된 기사를 조건별로 검색하고 페이지 단위로 반환한다 |
| 실행 관리 | 실행을 비동기로 수행하고 상태와 이력을 기록한다 |
| 자동 실행 | 매일 지정 시각에 수집을 자동으로 수행한다 |

### 2.3 사용자 특성

| 사용자 | 특성 | 주요 활동 |
|---|---|---|
| 일반 사용자 | 웹 사용에 익숙한 개인 | 설정 등록, 기사 열람, 수동 실행 |
| 운영자 | 시스템 설치·유지 담당 | 환경 구성, 실행 이력 점검 |

본 릴리스는 단일 사용자 운영을 전제로 하며, 사용자 구분은 데이터 구조에만 반영한다.

### 2.4 운영 환경

| 구분 | 요구사항 |
|---|---|
| 서버 실행 환경 | 컨테이너 실행이 가능한 환경 |
| 데이터베이스 | 관계형 데이터베이스. UTF-8 다국어 문자 지원 필요 |
| 클라이언트 | 최신 버전의 데스크톱 웹 브라우저 |
| 네트워크 | 외부 HTTPS 및 SMTP 송신이 가능해야 함 |

### 2.5 제약사항

| ID | 내용 |
|---|---|
| CON-01 | 수집 대상은 공개된 RSS 피드로 한정한다 |
| CON-02 | 대상 사이트의 이용 약관 및 robots.txt를 준수한다 |
| CON-03 | 기사 본문은 저장·재배포하지 않는다. 제목·링크·발행일시만 취급한다 |
| CON-04 | 메일 발송은 발신 계정의 일일 한도를 초과하지 않는다 |
| CON-05 | 개인 학습 및 개인 사용 목적으로 한정한다 |

### 2.6 가정 및 의존성

| ID | 내용 |
|---|---|
| ASM-01 | 대상 RSS 피드가 안정적으로 제공된다 |
| ASM-02 | 외부 SMTP 서비스를 사용할 수 있다 |
| ASM-03 | 동시 사용자 수는 5명 이하이다 |
| ASM-04 | 수집 대상 피드 소스는 20개 이하, 키워드는 20개 이하이다 |

## 3. 인터페이스 요구사항

### 3.1 사용자 인터페이스

| ID | 요구사항 | 출처 |
|---|---|---|
| SR-I-101 | 시스템은 설정 화면을 제공하고 키워드·메일 제목·수신자·최대 건수를 입력받아야 한다 | UR-CFG-01, 06, 07 |
| SR-I-102 | 시스템은 피드 소스 관리 화면을 제공하고 등록·수정·삭제·활성 여부 변경을 지원해야 한다 | UR-CFG-02, 05 |
| SR-I-103 | 시스템은 기사 목록 화면을 제공하고 키워드·피드 소스 필터와 페이지 이동을 지원해야 한다 | UR-STO-02~04 |
| SR-I-104 | 시스템은 수집 즉시 실행 기능과 진행 상태 표시를 제공해야 한다 | UR-EXE-01, 04 |
| SR-I-105 | 실행 실패 시 화면에 실패 사유를 표시해야 한다 | UR-EXE-05 |
| SR-I-106 | 입력값 오류 시 해당 항목과 사유를 화면에 표시해야 한다 | UR-NFR-11 |

### 3.2 외부 시스템 인터페이스

| ID | 요구사항 | 출처 |
|---|---|---|

| SR-I-202 | 시스템은 요청 시 식별 가능한 User-Agent를 전송해야 한다 | CON-02 |
| SR-I-203 | 시스템은 SMTP over TLS를 통해 HTML 메일을 발송할 수 있어야 한다 | UR-DLV-01 |
| SR-I-204 | SMTP 접속 정보는 환경 변수로 주입되어야 한다 | UR-NFR-05 |

### 3.3 내부 인터페이스 (API)

클라이언트와 서버 간 인터페이스는 REST 방식의 JSON API로 한다. 상세 명세는 부록 A를 따른다.

| ID | 요구사항 | 출처 |
|---|---|---|
| SR-I-301 | 요청 및 응답 본문은 UTF-8 인코딩의 JSON이어야 한다 | — |
| SR-I-302 | 속성명은 snake_case를 사용해야 한다 | — |
| SR-I-303 | 일시 값은 ISO 8601 UTC 형식으로 표현해야 한다 | UR-DAT-04 |
| SR-I-304 | 목록 응답은 total_count, page, items_per_page, items 속성을 포함해야 한다 | UR-STO-04 |
| SR-I-305 | 오류 응답은 code, message 속성을 포함해야 하며 입력값 오류 시 fields를 추가해야 한다 | UR-NFR-11 |
| SR-I-306 | 서버는 지정된 출처의 교차 출처 요청을 허용해야 한다 | — |

## 4. 기능 요구사항

### 4.1 설정 관리 (SR-F-1xx)

| ID | 요구사항 | 출처 |
|---|---|---|
| SR-F-101 | 시스템은 설정 조회 시 키워드 목록, 메일 제목, 수신자 주소, 소스당 최대 수집 건수를 반환해야 한다 | UR-CFG-01 |
| SR-F-102 | 키워드는 1자 이상 64자 이하이며 최대 20개까지 등록할 수 있어야 한다 | UR-CFG-01 |
| SR-F-103 | 시스템은 동일한 키워드의 중복 등록을 허용하지 않아야 한다 | UR-CFG-01 |
| SR-F-104 | 수신자 주소는 RFC 5322 형식을 만족해야 하며 불만족 시 400을 반환해야 한다 | UR-CFG-07 |
| SR-F-105 | 소스당 최대 수집 건수는 1 이상 100 이하의 정수여야 한다 | UR-CFG-06 |
| SR-F-106 | 메일 제목은 1자 이상 200자 이하여야 한다 | UR-CFG-07 |
| SR-F-107 | 설정 변경은 저장 즉시 유효하며 다음 실행부터 반영되어야 한다 | UR-NFR-07 |

### 4.2 피드 소스 관리 (SR-F-2xx)

| ID | 요구사항 | 출처 |
|---|---|---|
| SR-F-201 | 시스템은 피드 소스 등록 시 표시명, 주소 템플릿, 정렬 순서, 활성 여부를 저장해야 한다 | UR-CFG-02, 03 |
| SR-F-202 | 주소 템플릿은 `http://` 또는 `https://` 로 시작해야 하며 불만족 시 400을 반환해야 한다 | UR-CFG-03 |
| SR-F-203 | 주소 템플릿에 포함된 `{keyword}` 문자열은 수집 시 키워드로 치환되어야 한다 | UR-CFG-04 |
| SR-F-204 | 치환 시 키워드는 URL 인코딩되어야 한다 | UR-CFG-04 |
| SR-F-205 | `{keyword}`를 포함하지 않는 주소 템플릿도 등록할 수 있어야 하며, 이 경우 키워드 수와 무관하게 1회만 조회한다 | UR-CFG-03 |
| SR-F-206 | 표시명은 중복될 수 없다 | UR-CFG-02 |
| SR-F-207 | 활성 여부가 거짓인 피드 소스는 수집 대상에서 제외되어야 한다 | UR-CFG-05 |
| SR-F-208 | 피드 소스 삭제 시 해당 소스로 수집된 기존 기사는 유지되어야 한다 | UR-STO-01 |
| SR-F-209 | 정렬 순서는 정수이며 동일 값이 있을 경우 표시명 오름차순으로 처리한다 | UR-CFG-08 |

## 5. 데이터 요구사항

### 5.1 데이터 항목

**설정 (Setting)**

| 항목 | 형식 | 필수 | 설명 |
|---|---|---|---|
| `mail_subject` | 문자열(200) | 예 | 발송 메일 제목 |
| `mail_to` | 문자열(255) | 예 | 수신자 주소 |
| `max_per_source` | 정수 | 예 | 소스당 최대 수집 건수 |
| `keywords` | 문자열 목록 | 예 | 검색 키워드 |

**피드 소스 (FeedSource)**

| 항목 | 형식 | 필수 | 설명 |
|---|---|---|---|
| `id` | 문자열(26) | 예 | 식별자 |
| `name` | 문자열(64) | 예 | 표시명. 중복 불가 |
| `url_template` | 문자열(1000) | 예 | 주소 템플릿 |
| `sort_order` | 정수 | 예 | 정렬 순서 |
| `is_active` | 불리언 | 예 | 활성 여부 |

**기사 (Article)**

| 항목 | 형식 | 필수 | 설명 |
|---|---|---|---|
| `id` | 문자열(26) | 예 | 식별자 |
| `title` | 문자열(500) | 예 | 기사 제목 |
| `link` | 문자열(1000) | 예 | 원문 링크 |
| `link_hash` | 문자열(64) | 예 | 정규화 링크의 SHA-256. 유일해야 함 |
| `keyword` | 문자열(64) | 예 | 수집에 사용된 키워드 |
| `site` | 문자열(64) | 예 | 피드 소스 표시명 |
| `published_at` | 일시 | 아니오 | 발행일시 |
| `collected_at` | 일시 | 예 | 수집일시 |
| `summary` | 문자열 | 아니오 | 요약. 본 릴리스 미사용 |
| `user_id` | 문자열(26) | 예 | 사용자 구분. 단일 값 운용 |

**실행 (Execution)**

| 항목 | 형식 | 필수 | 설명 |
|---|---|---|---|
| `id` | 문자열(26) | 예 | 실행 식별자 |
| `status` | 문자열(16) | 예 | queued / running / success / failed |
| `started_at` | 일시 | 예 | 시작 시각 |
| `finished_at` | 일시 | 아니오 | 종료 시각 |
| `collected_count` | 정수 | 예 | 수집 건수 |
| `new_count` | 정수 | 예 | 신규 건수 |
| `error` | 문자열 | 아니오 | 실패 사유 |
| `node_logs` | JSON | 아니오 | 소스별 처리 결과 |

## 부록 B. 처리 흐름 및 상태 전이

### B.1 수집 실행 처리 흐름

| 단계 | 처리 | 관련 요구사항 |
|---|---|---|
| 1 | 실행 요청 수신. 진행 중인 실행이 있으면 409 반환 후 종료 | SR-F-705 |
| 2 | 실행 식별자 생성, 상태를 queued로 기록, 작업 큐에 등록 | SR-F-701 |
| 3 | 202와 함께 실행 식별자 반환 (여기까지 API 서버) | SR-F-701 |
| 4 | 작업 처리기가 작업을 가져가고 상태를 running으로 변경 | SR-F-702 |
| 5 | 설정 및 활성 피드 소스 조회 | SR-F-101, 207 |
| 6 | 수집 주소 생성 (키워드 × 피드 소스) | SR-F-301, 203 |
| 7 | 동시 3건 이내로 HTTP GET 수행 및 피드 파싱 | SR-F-302, 306, 307 |
| 8 | 개별 주소 실패 시 0건 처리 후 로그 기록, 나머지 계속 | SR-F-308 |
| 9 | 주소별 최대 건수 적용 | SR-F-309 |
| 10 | 링크 정규화 및 해시 산출 | SR-F-401, 402 |
| 11 | 실행 내 중복 제거 | SR-F-404 |
| 12 | 저장소 대비 신규 여부 판정 | SR-F-405 |
| 13 | 신규 기사 저장 | SR-F-601 |
| 14 | 정렬 수행 | SR-F-406, 407 |
| 15 | 신규 0건이면 발송을 생략하고 success로 종료 | SR-F-507 |
| 16 | HTML 본문 생성 및 메일 발송 | SR-F-501, 506 |
| 17 | 상태를 success로 변경하고 집계 기록 | SR-F-703 |
| — | 처리 중 예외 발생 시 상태를 failed로 변경하고 사유 기록 | SR-N-204 |

### B.2 실행 상태 전이

| 현재 상태 | 다음 상태 | 전이 조건 |
|---|---|---|
| — | `queued` | 실행 요청이 접수되어 큐에 등록됨 |
| `queued` | `running` | 작업 처리기가 작업을 가져감 |
| `running` | `success` | 발송 완료 또는 신규 0건으로 정상 종료 |
| `running` | `failed` | 전체 수집 실패, 발송 실패, 또는 처리 중 예외 |
| `queued` | `failed` | 큐 등록 후 처리기가 시작하지 못함 |

`success` 및 `failed`는 최종 상태이며 다른 상태로 전이하지 않는다.

### C.1 추적 파라미터 제거 대상

SR-F-403에 따라 링크 정규화 시 다음 질의 파라미터를 제거한다.

```
utm_source    utm_medium    utm_campaign
utm_term      utm_content   fbclid
gclid         ref           oc
```

목록은 운영 중 추가될 수 있으며, 변경 시 본 문서를 개정한다.
